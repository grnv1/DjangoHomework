## P2 核心机制（约 90 秒）—— 只讲最能证明"理解"的两点

**页面内容**
- 三级权限：靠 `is_staff` / `is_superuser` 标志位，不用 Django 模型权限
  - 超级管理员：全部权限
  - 内容管理员：仅能操作**自己创建**的文章
  - 普通用户：前台浏览
- 发布与可见性：**未删除 + 已发布 + 发表时间 ≤ 当前时间** 才前台可见
  - 支持定时发布（发表时间设为未来）
  - 表单提供「存草稿 / 发布」两个动作，草稿保留发表时间

**讲稿**
> 系统最核心的是权限和发布机制。权限分为三级：超级管理员、内容管理员、普通用户。实现上只用 Django 内置的 `is_staff`、`is_superuser` 两个标志位，在视图层做拦截；内容管理员在数据层只能看到、操作自己创建的文章，访问他人文章返回 403。
>
> 发布机制上，一篇文章只有"未删除、已发布、且发表时间到了"才会在前台出现，所以支持把发表时间设成未来做定时发布。表单里用「存草稿 / 发布」两个按钮，存草稿会保留你填好的发表时间。

## 建议砍掉、口头补充的内容（被追问时再说）

- **技术选型理由**：为什么 Django —— 内置 ORM / 认证 / 迁移 / 表单，SQLite 文件库便于复现
- **数据模型**：5 张表（Category / Item / Tag 多对多 / Favorite / OperationLog），公共基类记录创建更新与软删除
- **软删除**：栏目 / 文章删除为逻辑删除（置 is_deleted），默认管理器自动过滤
- **操作日志**：记录栏目 / 文章的创建、更新、删除
- **收藏 / 浏览量**：登录用户收藏、详情页浏览量 +1
- **查询细节**：四种条件（含标签）可组合，AND 关系，日期区间含当天
- **示例数据**：3 账号（admin / wang / zhangsan）、3 栏目、8 文章、3 标签；`migrate + seed + runserver` 三步复现
