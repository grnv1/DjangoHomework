# CMS 内容管理系统 — 部署说明

本系统为基于 Django 6 的内容管理系统（CMS），Python 3.12 + Django 6.0 + SQLite，前后端一体（服务端模板渲染，无需单独部署前端）。

## 一、环境依赖

| 依赖 | 版本要求 | 说明 |
|---|---|---|
| Python | 3.12+ | 开发语言 |
| Django | 6.0.8 | Web 框架（`requirements.txt` 已锁定） |
| SQLite | 无需安装 | Python 内置，数据库文件为 `db.sqlite3` |
| ruff | 0.16.2 | 代码规范检查工具（可选） |

运行环境无需额外安装 MySQL / Redis 等中间件；Windows / Linux / macOS 均可。

## 二、安装步骤

### 1. 获取代码

```bash
git clone <仓库地址>
cd DjangoProject
```

### 2. 创建并激活虚拟环境（推荐）

Windows：

```bat
python -m venv venv
venv\Scripts\activate
```

Linux / macOS：

```bash
python3 -m venv venv
source venv/bin/activate
```

### 3. 安装依赖

```bash
pip install -r requirements.txt
```

> 只安装运行依赖可执行 `pip install Django==6.0.8`，`ruff` 用于代码检查，可不装。

## 三、数据库迁移

首次部署（或数据库文件不存在时）执行：

```bash
python manage.py migrate
```

> 命令会创建 `db.sqlite3` 及全部数据表（含 Django 内置表）。后续若模型有变更，同样执行该命令应用新迁移。

生成示例数据（可选，含演示账号与演示文章，便于体验）：

```bash
python manage.py seed
```

> 示例数据包括：3 个账号、3 个栏目、8 篇演示文章（含定时发布与草稿）、30 篇分页测试文章、若干标签与收藏。

## 四、启动命令

### 方式一：一键启动（Windows）

双击 `start.bat`，脚本自动完成 `migrate`（必要时 `seed`）并启动服务。

### 方式二：手动启动

```bash
python manage.py migrate     # 首次需执行
python manage.py runserver   # 默认端口 8000
```

指定端口：

```bash
python manage.py runserver 0.0.0.0:8000
```

访问地址：

- 前台：`http://127.0.0.1:8000`
- 管理后台：`http://127.0.0.1:8000/admin/`（需登录且为管理员）

## 五、测试命令

运行单元测试（共 28 个用例）：

```bash
python manage.py test cms
```

运行 PEP 8 代码规范检查：

```bash
python -m ruff check .
```

## 七、常见问题

| 现象 | 处理 |
|---|---|
| 端口被占用 | 换端口启动：`python manage.py runserver 8080` |
| 首页无任何文章 | 未执行 `seed`，或文章为草稿 / 定时未到发表时间（可见性规则：未删除 + 已发布 + 发表时间 ≤ 当前时间） |
| 数据库结构异常 | 删除 `db.sqlite3` 后重新 `migrate`（测试环境可操作，勿在生产环境使用） |
| 中文显示乱码 | 确认终端编码为 UTF-8；系统已配置 `LANGUAGE_CODE = "zh-hans"`、`TIME_ZONE = "Asia/Shanghai"` |
