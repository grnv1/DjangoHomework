# CMS 内容管理系统 — 需求文档

## 一、项目背景

内容管理系统（Content Management System，CMS）是一种管理信息、并将信息对外发布的软件系统。管理用户在系统中完成内容管理，普通用户在前台浏览内容。

本系统为课程作业原型，目标是交付一个"能运行、能解释、能复现、能迭代"的 CMS 原型系统。

## 二、技术选型

- 开发语言：Python
- Web 框架：Django 6.0
- 数据库：SQLite（`db.sqlite3`，文件型数据库）
- 代码规范：PEP 8，关键逻辑编写必要注释

## 三、功能需求

### 1. 核心功能（必做）

- **实体对象**：系统至少包含两个实体对象 —— 栏目（Category）与文章（Item）。
- **管理功能**：管理用户可发布文章、选择栏目，并对文章、栏目进行增删改查（CRUD）。
- **浏览功能**：普通用户可浏览已发布（status=已发布）的文章内容。
- **查询功能**：系统前台主界面需提供查询功能，支持以下 3 种查询模式：
  1. 按文章题目查询（模糊匹配）
  2. 按发表时间查询（日期区间，起止日期）
  3. 按栏目查询（下拉选择栏目）

### 2. 扩展功能

- 分页：前台文章列表分页展示（条数可配置）
- 文章状态：草稿 / 已发布，前台仅显示已发布文章
- 定时发布：发表时间可设置为未来时间，到时文章自动对外可见
- 浏览量统计：每篇文章记录点击次数并在详情页展示
- 文章标签（Tag）：文章可关联多个标签，前台支持按标签查询。标签来源：文章表单支持从已有标签中选择，也可直接输入新标签名（保存文章时自动创建新标签）。
- 用户收藏：登录用户可收藏文章，并提供"我的收藏"页面。
- 操作日志：记录栏目 / 文章的关键操作（创建、更新、删除）。
- 软删除：栏目 / 文章删除为逻辑删除，数据不物理清除。

## 四、角色与权限

系统采用三级角色，基于 Django 内置用户模型与权限系统（`auth.Group` 用户组）实现：

| 角色 | 判定条件 | 权限范围 |
|---|---|---|
| 超级管理员 | `is_superuser=True` | 全部权限：管理用户、栏目、文章，查看操作日志 |
| 内容管理员 | `is_staff=True`、非超管、属于"内容管理员"组 | 栏目全部管理（仅空栏目可删除）；**只能**对自己创建的文章进行增删改查 |
| 普通用户 | `is_active=True` | 前台浏览文章、搜索、收藏文章 |

### 权限规则

- 角色权限通过 Django 权限系统（模型权限 + 用户组）定义与分配，超级管理员在后台用户管理中创建账号并分配角色。
- 内容管理员仅能查看、修改、删除自己创建的文章（`author` 为本人）；新建文章时作者自动取当前登录人，作者字段只读。
- 栏目删除仅允许删除"空栏目"（栏目下无未删除文章）；软删除的文章不计入空栏目判断。
- 内容管理员不可创建 / 管理后台用户。
- 栏目、文章删除采用**软删除**（置删除标记），不物理删除数据。
- 用户不提供物理删除，账号启停通过 `is_active` 控制；超级管理员不可停用 / 修改角色 / 删除当前登录本人账号。

## 五、数据模型设计

### 1. 用户表 `auth_user`（Django 内置）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | PK | 主键 |
| username | VARCHAR(150) UNIQUE | 用户名 |
| password | VARCHAR(128) | 加密存储 |
| email | VARCHAR(254) | 邮箱 |
| is_staff / is_superuser | BOOL | 是否为管理员 / 超级管理员 |
| is_active | BOOL | 是否启用 |
| date_joined | DATETIME | 创建时间 |

### 2. 栏目表 `cms_category`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| name | VARCHAR(50) | NOT NULL, UNIQUE | 栏目名称 |
| description | TEXT | 可空 | 栏目简介 |
| created_at / created_by | DATETIME / FK→auth_user | NOT NULL | 创建时间 / 创建人 |
| updated_at / updated_by | DATETIME / FK→auth_user | NOT NULL | 更新时间 / 更新人 |
| is_deleted / deleted_at / deleted_by | BOOL / DATETIME / FK→auth_user | 默认 False | 软删除标记 / 删除时间 / 删除人 |

### 3. 文章表 `cms_item`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| title | VARCHAR(200) | NOT NULL | 文章题目 |
| content | TEXT | NOT NULL | 文章正文 |
| category | FK → cms_category | NOT NULL, PROTECT | 所属栏目（防物理误删，空栏目删除由应用层校验） |
| status | SMALLINT | 默认 0, 索引 | 0=草稿，1=已发布 |
| views | INT | 默认 0 | 浏览量 |
| author | FK → auth_user | NOT NULL | 作者（创建时自动取当前登录管理员） |
| publish_time | DATETIME | 可空, 索引 | 发表时间（**仅发布时有值**，供时间查询） |
| created_at / created_by | DATETIME / FK→auth_user | NOT NULL | 创建时间 / 创建人 |
| updated_at / updated_by | DATETIME / FK→auth_user | NOT NULL | 更新时间 / 更新人 |
| is_deleted / deleted_at / deleted_by | BOOL / DATETIME / FK→auth_user | 默认 False | 软删除标记 / 删除时间 / 删除人 |

### 4. 标签表 `cms_tag`（多对多）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| name | VARCHAR(50) | NOT NULL, UNIQUE | 标签名称 |

文章与标签为多对多关系，Django 自动生成中间表 `cms_item_tags`（item_id, tag_id）。

> **唯一性与软删除**：`cms_category.name` 与 `cms_tag.name` 虽定义为 UNIQUE，但由于采用软删除，重复名称校验**仅针对未删除（is_deleted=False）记录**执行。实现时在应用层保存逻辑中校验"未删除记录中是否存在同名"，避免软删除后无法重建同名栏目 / 标签。

### 5. 收藏表 `cms_favorite`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| user | FK → auth_user | NOT NULL, CASCADE | 收藏者 |
| item | FK → cms_item | NOT NULL, CASCADE | 被收藏文章 |
| created_at | DATETIME | NOT NULL | 收藏时间 |

- 联合唯一约束（user, item）：同一用户不能重复收藏同一篇文章。
- 文章软删除后，其收藏记录保留但不前台展示。

### 6. 操作日志表 `cms_operation_log`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| operator | FK → auth_user | NOT NULL | 操作人 |
| action | VARCHAR(20) | NOT NULL | 操作类型：create / update / delete |
| target_type | VARCHAR(20) | NOT NULL | 对象类型：item / category |
| target_id | INT | NOT NULL | 对象 ID |
| description | TEXT | 可空 | 操作说明（如"删除文章《标题》"） |
| created_at | DATETIME | NOT NULL | 操作时间 |

> **日志记录机制**：由管理端视图层调用统一日志函数记录（不在模型 signal 中记录，保证权限上下文与操作人明确）；栏目 / 文章的创建、更新、删除（含软删除）各记一条日志；软删除记为 `delete`。仅超级管理员可查看。

## 六、文章发布流程与可见规则

`status` 与 `publish_time` 是两个正交的概念：`status` 表示内容生命周期状态（草稿 / 已发布），`publish_time` 表示对外可见的时间点（仅对已发布文章生效，草稿时为空）。

### 可见规则

**一篇文章仅当"未删除"且 `status = 1（已发布）` 且 `publish_time <= 当前时间` 时，才在前台可见。**

| status | publish_time | 前台表现 |
|---|---|---|
| 草稿 | 空 | 永不显示 |
| 已发布 | 未来时间 | 定时发布，到时自动显示 |
| 已发布 | ≤ 当前时间 | 正常显示 |

### 发布流程

1. 管理端文章表单提供「存草稿 / 发布」两个动作：存草稿置 status=0，发布置 status=1。
2. 发表时间 `publish_time` 可手动设置（如定时或回溯日期）。
3. 点击发布（status=1）时，若 `publish_time` 为空，则自动取当前时间。
4. **草稿时间规则**：保存为草稿（status=0）时，**保留**表单中已填写的 `publish_time`，便于下次直接发布；从草稿转为发布时，若未填写则自动取当前时间，若已填写则保留。
5. 前台仅展示"未删除、已发布且已到发表时间"的文章。

## 七、前台与管理端功能页面

### 前台页面（普通用户 / 游客）

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 主页 | 未删除且已发布的文章列表 + 分页 + 查询区（标题 / 时间 / 栏目 / 标签，可组合查询） |
| `/item/<id>/` | 文章详情 | 正文、浏览量 +1、标签展示、收藏按钮 |
| `/category/<id>/` | 栏目页面 | 该栏目下已发布文章列表 + 分页 + 栏目内查询 |
| `/favorites/` | 我的收藏 | 收藏的文章列表、取消收藏 |
| `/register/` | 注册页 | 前台用户自助注册 |
| `/login/` `/logout/` | 登录 / 登出 | 用户登录与登出 |

### 管理端页面（自建，需登录且为管理员）

| 路由 | 页面 | 说明 |
|---|---|---|
| `/admin/` | 后台首页 | 统计概览 + 功能入口 |
| `/admin/category/` | 栏目管理 | 栏目增删改查（仅空栏目可删） |
| `/admin/item/` | 文章管理 | 文章增删改查（内容管理员仅见自己创建的文章） |
| `/admin/user/` | 用户管理 | 创建 / 启停管理员与普通用户（仅超级管理员） |
| `/admin/log/` | 操作日志 | 查看关键操作记录（仅超级管理员） |

## 八、查询功能设计

- 前台主页查询区含四个独立输入区域：标题关键词输入框、发表时间起止日期选择器、栏目下拉选择、标签下拉选择。
- 栏目页在栏目内查询：栏目由 URL 固定，可叠加标题 / 发表时间 / 标签条件。
- 填写任意条件即生效，多个条件同时填写时为 AND（并且）组合过滤。
- 查询结果统一以文章列表 + 分页展示。
- 仅对"未删除、已发布且已到发表时间"的文章进行查询展示。
- **日期区间实现细节**：`publish_time` 为 datetime 类型，`date_to` 表示"含当天"，查询时按当天 23:59:59 处理（`date_from` 当天 00:00:00 起、`date_to` 当天 23:59:59 止），避免漏掉当天晚些时候发表的文章。
- **分页参数保留**：首页 / 栏目页 / 收藏页 / 后台列表翻页时，当前查询与筛选参数（title、date、category、tag、status 等）需随分页链接一并保留。

## 九、非功能需求

- 代码遵循 PEP 8 规范；类、函数有 docstring；关键逻辑加必要注释。
- 必须建立 Git 版本库并持续、分步提交，禁止一次性提交全部代码。
- 界面使用中文（`LANGUAGE_CODE = "zh-hans"`），时区 `Asia/Shanghai`。
- 分页条数通过配置常量设定，可修改。
- 提供示例数据脚本与使用说明（README），保证可复现。

## 十一、验收标准

1. 系统可启动（`python manage.py runserver`）。
2. 超级管理员可创建内容管理员账号与普通用户，且不可操作自己的账号。
3. 内容管理员可增删改查栏目与**自己创建**的文章，无法操作他人文章。
4. 栏目删除受"空栏目"限制；文章 / 栏目删除为软删除，前台不可见。
5. 普通用户可注册、登录、浏览、搜索（标题 / 时间 / 栏目 / 标签）、收藏文章。
6. 前台文章列表分页，仅显示未删除、已发布且已到发表时间的文章（支持定时发布）。
7. 栏目 / 文章的关键操作（创建、更新、删除）记录于操作日志。
8. 创建 / 更新时记录操作人（created_by / updated_by）。
9. Git 仓库存在且提交记录连贯、分步。
