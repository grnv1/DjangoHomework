# CMS 内容管理系统 — 需求文档

## 一、项目背景

内容管理系统（Content Management System，CMS）是一种管理信息、并将信息对外发布的软件系统。管理用户在系统中完成内容管理，普通用户在前台浏览内容。

本系统为课程作业原型，目标是交付一个"能运行、能解释、能复现、能迭代"的 CMS 原型系统。

## 二、技术选型

- 开发语言：Python
- Web 框架：Django 6.0
- 数据库：SQLite（`db.sqlite3`，文件型数据库）
- 代码规范：PEP 8，关键逻辑编写必要注释

## 三、功能需求

### 1. 核心功能（必做）

- **实体对象**：系统至少包含两个实体对象 —— 栏目（Category）与文章（Item）。
- **管理功能**：管理用户可发布文章、选择栏目，并对文章、栏目进行增删改查（CRUD）。
- **浏览功能**：普通用户可浏览已发布（status=已发布）的文章内容。
- **查询功能**：系统前台主界面需提供查询功能，支持以下 3 种查询模式：
  1. 按文章题目查询（模糊匹配）
  2. 按发表时间查询（日期区间，起止日期）
  3. 按栏目查询（下拉选择栏目）

### 2. 扩展功能

- 分页：前台文章列表分页展示
- 文章状态：草稿 / 已发布，前台仅显示已发布文章
- 浏览量统计：每篇文章记录点击次数并在详情页展示
- 文章标签（Tag）：文章可关联多个标签
- 用户收藏：登录用户可收藏文章，并提供"我的收藏"页面

## 四、角色与权限

系统采用三级角色，通过 Django 内置用户模型的字段区分：

| 角色 | 判定条件 | 权限范围 |
|---|---|---|
| 超级管理员 | `is_superuser=True` | 管理用户（创建普通管理员、普通用户、调整权限）、管理全部栏目与文章 |
| 普通管理员 | `is_staff=True` 且 `is_superuser=False` | 栏目增删改查（仅空栏目可删除）；**只能**对自己创建的文章进行增删改查 |
| 普通用户 | `is_active=True` | 前台浏览文章、搜索、收藏文章 |

### 权限规则

- 普通管理员账号由超级管理员在后台创建。
- 普通管理员仅能查看、修改、删除自己创建的文章（`author` 为本人）。
- 栏目删除仅允许删除空栏目（栏目下无文章）；`Item.category` 外键采用 `PROTECT` 约束保证。
- 普通管理员不可删除其他管理员创建的文章，不可创建/管理后台用户。

## 五、数据模型设计

### 1. 用户表 `auth_user`（Django 内置）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | PK | 主键 |
| username | VARCHAR(150) UNIQUE | 用户名 |
| password | VARCHAR(128) | 加密存储 |
| email | VARCHAR(254) | 邮箱 |
| is_staff / is_superuser | BOOL | 是否为管理员 / 超级管理员 |
| is_active | BOOL | 是否启用 |
| date_joined | DATETIME | 创建时间 |

### 2. 栏目表 `cms_category`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| name | VARCHAR(50) | NOT NULL, UNIQUE | 栏目名称 |
| description | TEXT | 可空 | 栏目简介 |
| created_at | DATETIME | NOT NULL | 创建时间 |

### 3. 文章表 `cms_item`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| title | VARCHAR(200) | NOT NULL | 文章题目 |
| content | TEXT | NOT NULL | 文章正文 |
| category | FK → cms_category | NOT NULL, PROTECT | 所属栏目（非空栏目不可删） |
| status | SMALLINT | 默认 0, 索引 | 0=草稿，1=已发布 |
| views | INT | 默认 0 | 浏览量 |
| author | FK → auth_user | NOT NULL | 作者（创建时自动取当前登录管理员） |
| publish_time | DATETIME | NOT NULL, 索引 | 发表时间（可手动设置，供时间查询） |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

### 4. 标签表 `cms_tag`（多对多）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| name | VARCHAR(50) | NOT NULL, UNIQUE | 标签名称 |

文章与标签为多对多关系，Django 自动生成中间表 `cms_item_tags`（item_id, tag_id）。

### 5. 收藏表 `cms_favorite`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INT PK | 自增 | 主键 |
| user | FK → auth_user | NOT NULL, CASCADE | 收藏者 |
| item | FK → cms_item | NOT NULL, CASCADE | 被收藏文章 |
| created_at | DATETIME | NOT NULL | 收藏时间 |

- 联合唯一约束（user, item）：同一用户不能重复收藏同一篇文章。

## 六、文章发布流程

1. 管理员新建文章，可保存为草稿（status=0），草稿在前台不可见。
2. 发表时间 `publish_time` 可手动设置（如定时或回溯日期）。
3. 点击发布（status=1）时，若未手动设置发表时间，则自动取当前时间。
4. 前台仅展示 status=1 的已发布文章。

## 七、前台功能页面

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 主页 | 已发布文章列表 + 分页 + 查询区（三个独立输入区域，可组合查询） |
| `/item/<id>/` | 文章详情 | 正文、浏览量 +1、标签展示、收藏按钮 |
| `/category/<id>/` | 栏目页面 | 该栏目下已发布文章列表 + 分页 |
| `/favorites/` | 我的收藏 | 收藏的文章列表、取消收藏 |
| `/register/` | 注册页 | 前台用户自助注册 |
| `/login/` `/logout/` | 登录 / 登出 | 用户登录与登出 |
| `/admin/` | 管理后台 | Django Admin（超级管理员、普通管理员） |

## 八、查询功能设计

- 三个独立输入区域：标题关键词输入框、发表时间起止日期选择器、栏目下拉选择。
- 填写任意条件即生效，多个条件同时填写时为 AND（并且）组合过滤。
- 查询结果统一以文章列表 + 分页展示。
- 仅对已发布文章进行查询展示。

## 九、非功能需求

- 代码遵循 PEP 8 规范；类、函数有 docstring；关键逻辑加必要注释。
- 必须建立 Git 版本库并持续、分步提交，禁止一次性提交全部代码。
- 界面使用中文（`LANGUAGE_CODE = "zh-hans"`）。
- 提供示例数据脚本与使用说明（README），保证可复现。

## 十、Git 提交计划

1. `git init` + `.gitignore` + 项目骨架 → 初始提交
2. 创建 `cms` 应用 + 数据模型 + 迁移文件 → 提交

5. 查询功能（标题 / 时间 / 栏目三模式）→ 提交

7. 样式美化、测试、示例数据、README → 提交

## 十一、验收标准

1. 系统可启动（`python manage.py runserver`）。
2. 超级管理员可创建普通管理员与普通用户。
3. 普通管理员可增删改查栏目与**自己创建**的文章，无法操作他人文章。
4. 栏目删除受"空栏目"限制。
5. 普通用户可注册、登录、浏览、搜索（三种模式）、收藏文章。
6. 前台文章列表分页，仅显示已发布文章。
7. Git 仓库存在且提交记录连贯、分步。
